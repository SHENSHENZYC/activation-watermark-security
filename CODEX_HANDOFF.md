## 1. What this project is

A security analysis of an activation-steering LLM watermark (LLM Self-Recognition, ICML 2026): a secret vector added to
one hidden layer during generation and detected by re-encoding the text with the same open-weight model. Six
pre-registered, locked studies on Qwen2.5-1.5B measured, against a passive attacker who holds the weights and up to
1,024 watermarked outputs but cannot query the detector: forgery of the scheme's trained probe without the key; an exact
key-resampling score test (GaussMark's statistic transferred to an additive activation vector); key recovery from the
attacker's outputs with that same statistic; paraphrase and edit scrubbing at matched quality; and context-keyed and
rotating directions as defences (transfers from token-level watermarking) with their robustness cost. The author is
Yichen Zhao, an independent researcher. The paper's headline is "to our knowledge, the first security analysis of an
activation-steering LLM watermark"; every mechanism it uses is named as a transfer. The text and code were drafted by
Claude (Anthropic) under Yichen's direction, which the acknowledgements disclose; Yichen takes full responsibility and
reads everything before posting.

The paper is finished and approved at section level. What remains before posting is a final review and revision (your
task), Yichen's own full read, and the posting checklist in `RESEARCH_HANDOFF.md`.

## 3. Hard rules (each one protects the audit trail; none is negotiable)

1. **Never edit a locked file.** Everything hashed in any `research/outputs/*/PRE_RUN_LOCK.json` (the fields `protocol`,
   `code_sha256`, `reused_sha256`, `input_sha256`) is locked: every protocol, every runner and pilot script, the reused
   data files, the validation reports and results. The runners refuse to run on a mismatch, and a changed hash would
   break the paper's Table 1, which re-hashes them. To list the locked files:
   `python3 -c "import json,glob; s=set(); [s.update(list(d.get(k,{}).keys())+[d['protocol']]) for p in glob.glob('research/outputs/*/PRE_RUN_LOCK.json') for d in [json.load(open(p))] for k in ('code_sha256','reused_sha256','input_sha256')]; print(len(s)); print('\n'.join(sorted(s)))"`
   Also never edit anything under `research/outputs/` or `research/stage4/outputs/`, and never re-run a study (hours of
   compute; the results are locked).
2. **No number is typed by hand.** Every number in a section file is a `[[placeholder]]` registered by a committed script
   from a locked file; `fill_sections.py` fails on an unresolved name. If a number looks wrong, trace it: the placeholder's
   name → `grep -rn "name" research/paper/tables research/paper/figures` → the registering script → the `results.json`
   it reads. Fix the script if the script is wrong (it must still assert against the locked file), report in the memo if
   the locked result is what it is. The only numbers typed in prose are quotations from cited papers, with their PDF
   pages (§6 of the paper is the example).
3. **Quotations carry a PDF page and were confirmed by substring search** in a `pdftotext` extraction. The PDFs are
   git-ignored; restore them with `python3 research/literature/download_pdfs.py` and `download_regulator_pdfs.py` (one
   request per file, 3.5 s apart, per `research/literature/TERMS_OF_USE_CHECK.md`), extract with `pdftotext` to a scratch
   folder, and confirm before you change or add any quotation. Never quote from a search snippet or a summarising tool.
4. **The twelve wording rules** of `research/CLAIM_GATE_v0.1.md` §6 bind every sentence: "to our knowledge" on the
   headline and no "first" in the title; transfers named with their originators; the bounds (one model, one layer, 8 keys,
   256 tokens, the strengths, the attacker family, n ≤ 1,024) in every claim; attacker, budget and access in every security
   sentence; "exact on average over keys"; inferences labelled ("we read this as", "consistent with"); exploratory and
   post-hoc readings labelled wherever they appear; regulator texts for vocabulary and motivation only, never a compliance
   statement.
5. **Approved text.** Every section was approved by Yichen at section level. Revise for correctness, consistency, clarity
   and concision. Do not change what a claim says, add a result, remove a bound or a label, or reword a judgement (a
   verdict, a recommendation, a characterisation of someone's work) without putting it to Yichen in the memo.
6. **The AI-use disclosure.** The acknowledgements paragraph in `sec9_conclusion.md` names Claude (Anthropic). If your
   revisions are substantive, the paragraph must also name the tool you are; propose the sentence in the memo and apply it
   only when Yichen approves. arXiv expects disclosure of significant text-generation use.
7. **Nothing leaves this repository.** Do not push to, create, or change the visibility of
   `SHENSHENZYC/activation-watermark-security` (the public snapshot's home, private and empty until posting); do not submit
   to arXiv; do not send any email; do not post anywhere. Commit to this repository's `main` after each meaningful step
   with a clear message, and push to `origin` (the project's convention).
8. **Record keeping.** Every change gets a dated entry in `research/DECISION_LOG.md` (what, why, which files, "Decided
   by: Codex" or "Decided by: Yichen"), timestamps in UTC with Central time in parentheses (CDT until 1 November). At the
   end of your session update the status line and the resume point at the top of `RESEARCH_HANDOFF.md`.
9. **Never download data or models, and never work around a blocked site** (a 403, a bot check or a cookie wall is a
   stop; record it as an access gap).
10. **Internal file references.** The assembly strips `(see build/…)` markers; repository paths such as

## 4. How the paper is built (run from the repository root; `.venv/bin/python` is the project's Python 3.12)

```bash
for s in research/paper/tables/*.py research/paper/figures/*.py; do .venv/bin/python "$s" || exit 1; done   # only when a script changed (about 10 minutes)
.venv/bin/python research/paper/fill_sections.py                 # fills every [[placeholder]]; fails on an unresolved one
python3 .claude/skills/citation-management/scripts/validate_citations.py research/paper/references.bib   # 0 errors expected (system python3)
.venv/bin/python research/paper/assemble.py --render              # PAPER_DRAFT_v0.1.md, PAPER_OPEN_ITEMS_v0.1.md, build/PAPER_DRAFT_v0.1.pdf, build/page_count.json (headless Chrome)
.venv/bin/python research/paper/make_latex.py                    # latex/main.tex, references.bib, figures, main.pdf (Tectonic), page_count_latex.json
.venv/bin/python research/paper/wordcount.py                     # prose words per section (650 words a page convention)
```

Pandoc pitfalls the converter already handles: a closing `$` followed by a digit is not a math delimiter (write
`$\rho \in \{[[levels_all]]\}$`, never `$\rho \in \{$…$\}$`); non-ASCII characters are mapped to macros; code paths and
hashes get break points; tables above seven columns are set smaller. After a rebuild, check `latex/page_count_latex.json`
and view any page whose table or figure moved (`pdftoppm -r 55 -png -f N -l N research/paper/latex/main.pdf out`).

**Step 2: the review memo, `research/paper/CODEX_REVIEW_v0.1.md`, before any change.** Sections:

   behind each number, the script that registers it and the locked file it reads; confirm the script asserts against that
   file; list any mismatch between the text and the locked results. Then do the same for §5's verdict sentences.
2. *Consistency.* A number that appears in several places (abstract, §1, §5, §7, §9, a table note) must come from the same

3. *Quotations.* Re-confirm, by substring search in the PDF extractions, every quotation in §1, §2, §6 and Appendix I
   with its page (the gates list them); report any that fails.
4. *Wording rules.* A pass over every section against the twelve rules; list violations with the sentence.
5. *Prose.* Clarity, repetition, sentences that carry more than one idea, undefined symbols or acronyms at first use,

   -ise, no em dashes in prose (the draft uses en dashes and colons). There is no page target to hit: the arXiv paper's
   length was decided (about 24–25 main pages); the condensed venue version comes later.
6. *Rendering.* The LaTeX PDF: tables that overflow or are unreadable, figure placement, caption text, the references
   list, overfull lines above 5 pt (`grep "Overfull" research/paper/latex/main.log`).
7. *The open wording calls* already waiting for Yichen (`PAPER_OPEN_ITEMS_v0.1.md`, Part 1): how much protocol rule text
   Appendix A keeps; whether the B.5 sketch stays in the appendix or becomes a footnote in §3; whether C.1's implementation
   clause stays; whether the 31-word C4 prompt excerpt in Appendix H is cut to its first clause. Give a recommendation on
   each with the trade-off.
8. *Proposed revisions, classified:* **do** (factual errors, broken references, rule violations, clarity edits that change
   no meaning), and **ask** (anything touching a claim, a verdict, a characterisation, a bound, a label, the title, the
   abstract's structure, the AI-use paragraph), each "ask" with 2–3 options and your recommendation first.

**Step 3: revisions.** Apply the "do" items in `research/paper/sections/*.md` only, in a few coherent commits (for
